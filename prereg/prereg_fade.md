# Pre-registration addendum: "Fade, don't forget", low-bit old tokens in a hybrid's FA layers (Qwen3.5-9B)

Items marked **[design]** will be fixed after the design discussion with the research bot and before the first decode. Each is then logged at the end with a time. Every other line is fixed now. Changes made after the first decoded run is scored are listed at the end, each with a time and a reason. This addendum reuses the Think-Local data, sampler, scorer and bootstrap (`prereg_tl.md`).

## Question
Think-Local showed that giving old tokens 0 bits fails: windowing the FA layers to prompt + last 2K costs 40 pp on math. Today's head and layer maps (exploratory) showed that all 32 FA KV heads and all 8 FA layers read far back. The question here is whether old tokens need to be **present** or **exact**. Specifically: does a complete but low-precision memory of the trace beat an exact but recent one at the same FA memory?

## Policy (FA layers only; GDN untouched; no training)
- Prompt tokens: exact (bf16). The prompt is small (52–822 tokens) and fragile; SL-2K, which drops it, scored ~1%.
- The last R = 2,048 generated tokens: exact (bf16).
- Older generated tokens: quantized to b bits once, irreversibly, as real storage would be. Emulated by quantize-dequantize in place in the bf16 cache, so memory is analytic, as in Think-Local.
- Quantizer (fixed 2026-10-27 ~17:55 UTC, see change log):
  - Plain variants are KIVI-style asymmetric. Keys are quantized per channel over blocks of 128 generated tokens, values per token in groups of 128 along head_dim. Scale and zero are stored in fp16, so effective bits are b + 0.25.
  - Hadamard variants rotate each head (head_dim 256), then quantize keys and values per token in groups of 128, then rotate back.
  - Keys are quantized post-RoPE, as cached. One pre-RoPE 2-bit variant is also swept.
  - A 128-token block is quantized for query position g once its last token is at or before g − R. So between 2,048 and 2,175 recent tokens stay exact.
- Analytic memory per sample: prompt + R tokens at 32 KiB/token, plus old tokens at 32 KiB × (b + 0.25)/16 per token, plus the 49 MiB GDN state. Reported as the mean over rows, as in the Think-Local trade-off plot.

## Cell selection (rule fixed now; uses only the teacher-forced KL sweep on the 40 held-out E1 traces, never the test problems)
- **Cell A (main):** b = 2 for keys and values. Among the 2-bit K+V variants in the sweep (plain, Hadamard, post- or pre-RoPE), the one with the lowest KL/tok.
- **Cell B (low end of the curve):** the variant with the fewest effective bits below 2 whose KL/tok is at most the KL/tok of TL-W8K windowing in the same sweep. If no variant below 2 bits qualifies, Cell B = 4-bit K+V (plain), which anchors the top of the curve instead.
- The sweep, its references (TL-W2K and TL-W8K windowing) and the chosen cells are logged here before the first decode starts.

## Data and sampling
- Math only: the 120 Think-Local problems (AIME25, AIME26, HMMT25, MATH-500 L5, 30 each), 32K cap, same sampler and scorer. Countdown is not run, for lack of time.
- New cells run k = 2 (samples 0–1). Samples 2–3 are added only if both new cells finish k = 2 by **2026-10-28 01:00 UTC**, and then for both cells. They are never added or stopped because of results.
- Comparators are the existing Think-Local runs with all 4 samples: Full, TL-W2K, TL-W4K, TL-W8K. Per-problem accuracy is the mean over that cell's own samples, so unequal k is allowed. Seeds are nominal, so every contrast pairs by problem.

## Primary analysis (one test)
- **Contrast:** math accuracy at the 32K cap, Cell A − TL-W8K. This is a matched-memory test: blurry but complete vs sharp but recent.
- **Estimator and CI:** as in `prereg_tl.md`. Paired by problem; two-sided 95% percentile CI from a cluster bootstrap that resamples problems within each dataset (10,000 resamples, seed 0).
- **Wording rule:**
  - CI lower bound > 0: "better than an 8K window at matched memory".
  - CI upper bound < 0: "worse".
  - Anything else: "inconclusive at n = 120".
- **Memory check:** if Cell A's analytic mean memory is more than 10% above TL-W8K's, the contrast is reported as "not memory-matched" next to its verdict.
- **Expected direction:** Cell A > TL-W8K, since every FA head reads far back.

## Secondary analyses (pre-specified, labelled secondary, no multiplicity correction)
- **Q1. Against Full:** Cell A − Full, math accuracy. Non-inferiority margin 5 pp, with the Think-Local wording rule (lower bound > −5: non-inferior; upper bound < 0: worse; upper bound < −5: worse by more than the margin; otherwise inconclusive).
- **Q2. The bits curve:** accuracy against bits per old token, with Cell B − TL-W2K and Cell B − Full as two-sided CIs, no margin. The curve's points are 0 bits (TL-W2K), Cell B, Cell A (2 bits) and 16 bits (Full).
- **Q3. Cost:** mean generated tokens, finished rate and cap-hit rate per cell, and the per-problem difference in tokens over finished runs, same bootstrap. Aggressive KV quantization is known to lengthen reasoning (ThinKV 2510.01290; 2512.12008), so length is reported next to every accuracy.
